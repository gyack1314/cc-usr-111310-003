# 批量守恒与谱系

量以非负有理数字符串表示，例如100、1/3；禁止浮点、负值、零分母。input/output量必须正，loss可0。raw_lots给初始总产生量，同一个raw批不能再由事件生产。事件输出批仅一个有效producer，已消耗量为全部有效事件对该批输入之和。输出产量与原料初量不因是否消耗完而改变。

均匀混合：事件输入各批的root贡献比例先乘实际消耗量，再汇成事件root输入量。每输出root贡献=该root输入量*输出量/总输入量，loss同理，所以输出不按去掉loss后的量重新归一。桥量针对批总产出，余额量单独报告。未消耗的b剩20在余额账而不消失。

撤回事件集合先形成候选有效账，再验证所有后代producer和余额，失去合法父来源必须拒绝整次撤回。初始源数据split损耗10、a与r2混合成c、b部分与c汇成d，形成r1两条路径汇合。unused为无关分支。初始代码只清点事件ID、类型和批身份。

## 桥表与谱系实现约定（warehouse_data.engine / report）

* 事件Event不可变，携带event_id、version、实际输入消耗量、实际输出产量与明确损耗；同event_id重放必须载荷完全一致，否则按不可变违规拒绝；撤回通过withdraw_event表达，不允许就地改事件。
* 桥表行为(root_lot, descendant_lot)的精确贡献量Fraction与比例quantity/批总产出；同根不同路径的贡献相加而非去重路径。可达性关系不等于贡献比例：比例只来自逐段实际数量折算，不按“能否到达”均分。
* 每个输出批的所有根贡献之和必须等于它的产量；损耗进独立损耗守恒账（loss_ledger与loss_paths），按同一均摊比例归属root，不把损耗重新摊给幸存品提高占比。全局守恒：原料初量 == 现存批余额 + 累计损耗。
* 余额：已产生量 == 全部有效事件消耗量 + 余额；输入消耗超过余额、重复生产者、原料批再被生产、自环或依赖成环、撤回后下游失去来源，都整批拒绝且不留下桥已变而余额未变的半成品（撤回在深拷贝候选账上重算并verify后才整体替换）。
* 返工必须产生新批身份，禁止给旧批加回边。
* 增量维护：新事件或撤回只沿实际后代闭包重算，闭包外输入沿用既有composition，无关分支不扫；last_affected给出受影响批清单。
* 每个发布版本绑定有效源事件集的sha256摘要（含event_id与version、已撤回集合），同一仓重复应用同一份清单幂等，不重复消耗。
* report输出bridge、balances、逐段trace_paths（每段带factor与精确quantity）、loss_paths、conservation与affected_lots；所有数量以字符串序列化，全程不经float。
